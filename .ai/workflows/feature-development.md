# Feature Development

1. **Requirements** — restate objective and acceptance criteria; ask about gaps. Do not guess.
2. **Inspect** — find similar existing features and follow their patterns.
3. **Affected components** — list modules, interfaces, data, configs, docs touched.
4. **Design** — STANDARD: short plan. HIGH RISK: formal plan + ADR when a lasting decision is made.
5. **Implement** — in small, reviewable commits; reuse abstractions; avoid new dependencies unless justified.
6. **Test** — write tests for each acceptance criterion; run the project's checks.
7. **Review** — self-review the diff against `code-review.md`.
8. **PR** — fill the PR template honestly (risk, rollback, verification status, AI assistance).
